# SPA rendering, canonical URLs and delivery

Live inspection and remediation, 2026-10-27.

## Initial HTML

The Express renderer already sends readable page content inside `#root` before JavaScript executes. The Persian `/catalog` response contained its Persian H1 and 110 product links. Product pages contained technical text/tables, and `/engineering` contained its reference-tool description. Category guides are also present in initial HTML. This applies to ordinary visitors and crawlers alike; no user-agent-specific rendering is used.

The app uses a shared server HTML renderer and client-side React views, rather than an empty public app shell. Interactive calculations and 3D views still require JavaScript. Server-side content is read from published SQLite records. Missing/archived routes retain their real 404 status.

## URL corrections

Language and filter variants already canonicalized correctly: `.com/catalog?lang=fa` points to the clean Persian `.ir/catalog`, and `.ir/catalog?lang=en` points to English `.com/catalog`. Search/filter parameters and trailing slashes are excluded from canonicals.

Two gaps were found and corrected:

- Encoded aliases such as `/product/%36%32%30%34-2rs` declared the encoded spelling as canonical. Valid encoded product slugs now normalize to `/product/6204-2rs` across canonical links, language alternatives and structured data. Invalid slugs retain ordinary missing-page behavior.
- The CMS link helper matched the entire `/catalog*` prefix and rewrote product links into homepage fragments. Dedicated category and product paths now remain intact. Legacy links targeting the homepage catalog/engineering sections keep their existing behavior.

Production initial HTML links now use the approved canonical language origin and clean paths, without redundant `?lang` aliases. Local previews retain explicit language controls. The SEO audit checks both relative links and absolute links to the company's own domains.

## Asset delivery correction

The preloaded IRANSans WOFF2 font and hashed scripts/styles were self-hosted and already returned `public, max-age=31536000, immutable`. Font faces use `font-display: swap`.

However, JavaScript was served as `text/javascript` while nginx's gzip list covered only `application/javascript`. A public GET requesting gzip transferred the full 264,018-byte main script without content encoding. The nginx templates now cover both JavaScript MIME types. The installed Ubuntu nginx 1.24 build supports HTTP/2; the TLS templates enable its compatible `listen ... http2` option. Apply these changes with a configuration backup, `nginx -t`, graceful reload and trusted-TLS checks. These changes do not require different fonts or product images.

## Performance baseline and interpretation

Official Lighthouse 13.5.0 was run in temporary headless Chrome profiles on this workstation against the live Persian homepage. The public PageSpeed API returned HTTP 403 and supplied no usable report. The audits did not use a signed-in browser profile or production credentials.

| Baseline | Mobile simulation | Desktop preset |
| --- | ---: | ---: |
| LCP | 1.87 s | 0.70 s |
| First contentful paint | 1.87 s | 0.70 s |
| Total blocking time | 2,446 ms | 608 ms |
| Cumulative layout shift | 0.018 | 0.017 |
| Lighthouse performance score | 62 | 69 |

The mobile preset used simulated 150 ms RTT, 1,638.4 Kbps throughput and 4× CPU slowdown. These are individual lab observations, not an Iran-wide benchmark or a real-user percentile. The substantial blocking time remains a performance concern even though the measured LCP was below 2.5 seconds. Changes in animation/runtime work require their own measured review; this task preserves the bearing models and motion.

Google's good LCP threshold is **2.5 seconds or less at the 75th percentile**, segmented by mobile and desktop. Sub-second LCP is a stricter target, not Google's general requirement. Neither pre-rendering nor a lab score guarantees ranking. After deployment, retain fresh lab reports and verify gzip, HTTP/2, clean canonicals and initial HTML directly. Report after-run measurements separately from these baseline samples; do not infer a field improvement percentage from one run.

Raw audit reports and public HTTP evidence are generated under the ignored `outputs/spa-seo/` directory. The optional audit tools are isolated under ignored `work/performance-audit/` and are not application dependencies.

## Boundaries

The indexing gate remains locked in runtime metadata and nginx headers. Engineering/catalog approval is still separate. Database records, media, SSH login and DNS are outside this change. Deployment backups stay on the VPS.
