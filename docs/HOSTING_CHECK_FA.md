# بررسی سرور پیش از انتشار سایت

وضعیت در ۲۰ مهر ۱۴۰۵ / 2026-10-12: VPS هنوز خریداری نشده و هیچ استقرار عمومی انجام نشده است. ابزار زیر برای آزمایش محیط واقعی پس از تحویل سرور آماده شده است؛ موفقیت روی رایانهٔ محلی به معنی تأیید هاست نیست.

## آزمایش اولیه

فایل `scripts/hosting-check.mjs` مستقل است و نصب وابستگی‌های پروژه لازم ندارد. Node.js نسخهٔ 22.16 یا جدیدتر باید از قبل روی سرور نصب باشد.

مسیر دائمی داده را هنگام راه‌اندازی ایجاد کنید و آزمایش را با همان کاربر لینوکسی اجرا کنید که برنامه را اجرا خواهد کرد؛ اجرای موفق با کاربر root، دسترسی کاربر برنامه را اثبات نمی‌کند. نمونه، پس از ایجاد کاربر و مسیرهای سرویس:

```bash
sudo -u polad-charkhesh node /opt/polad-charkhesh/current/scripts/hosting-check.mjs /var/lib/polad-charkhesh
```

ابزار یک پوشهٔ جدید با پیشوند `polad-hosting-probe-` می‌سازد و فقط با دادهٔ آزمایشی خودش کار می‌کند. فایل‌های سایت، محصولات، کاربران و تصاویر فعلی را باز یا تغییر نمی‌دهد. نتیجه به صورت JSON نمایش داده می‌شود و خطا باعث خروج با کد غیرصفر می‌شود.

موارد بررسی‌شده:

- امکان نوشتن فایل در مسیر انتخاب‌شده؛
- فعال شدن واقعی SQLite WAL؛
- بازیابی رکورد ثبت‌شده پس از خروج پردازش بدون بستن عادی پایگاه داده؛
- خواندن پایگاه داده هنگام باز بودن تراکنش نوشتن؛
- ایجاد نسخهٔ پشتیبان SQLite و بررسی سلامت و رکوردهای آن؛
- تطابق محتوای فایل آپلود آزمایشی با اثر انگشت ذخیره‌شده.

پوشهٔ آزمایش و خروجی را نگه دارید. اگر محل آپلودها روی دیسک یا mount جداگانه است، آزمایش را برای آن مسیر نیز اجرا کنید. ابزار برخی فایل‌سیستم‌های شناخته‌شدهٔ NFS/SMB/CIFS را رد می‌کند، اما شناسایی نکردن آن‌ها گواه محلی بودن ذخیره‌سازی نیست. نوع mount، پایداری و پشتیبانی از قفل‌گذاری فایل باید با ارائه‌دهنده و تنظیمات سرور بررسی شود.

## بررسی پس از راه‌اندازی مجدد یا انتشار نسخهٔ جدید

با هماهنگی مسئول سرور، ابتدا یک Restart واقعی سرور و سپس انتشار آزمایشی نسخهٔ جدید انجام دهید. بعد از هر کدام، مقدار `nextCheck` در گزارش اولیه را اجرا کنید. نمونه:

```bash
sudo -u polad-charkhesh node /opt/polad-charkhesh/current/scripts/hosting-check.mjs --verify /var/lib/polad-charkhesh/polad-hosting-probe-REPLACE_WITH_ACTUAL_SUFFIX
```

این مرحله سلامت پایگاه داده، بکاپ و فایل آزمایشی باقی‌مانده را بررسی می‌کند. خود ابزار سرور را Restart نمی‌کند و نمی‌تواند تشخیص دهد شما واقعاً Restart یا استقرار جدید انجام داده‌اید. زمان و نتیجهٔ هر عملیات را جدا ثبت کنید. وجود همیشگی فایل SHM لازم نیست؛ باقی ماندن صحیح دادهٔ ثبت‌شده مهم است.

پس از ثبت نتیجه، مدیر سرور می‌تواند فقط همان پوشهٔ اختصاصی آزمایش را حذف کند. ابزار هیچ پوشه‌ای را خودکار حذف نمی‌کند.

## مواردی که باید جداگانه تأیید شوند

| مورد | معیار پذیرش |
| --- | --- |
| اجرای خودکار | سرویس systemd پس از Restart و توقف ناگهانی برنامه دوباره اجرا شود |
| سلامت برنامه | `/api/health`، ورود مدیر و ذخیره و بازیابی یک تغییر آزمایشی موفق باشند |
| دامنه‌ها و HTTPS | هر دو دامنهٔ نهایی، گواهی معتبر و زبان صحیح داشته باشند |
| بکاپ واقعی | بازیابی نسخهٔ SQLite همراه رسانه‌ها در یک محیط جدا موفق باشد |
| منابع | مصرف RAM، CPU و دیسک با بار نماینده اندازه‌گیری شود |
| محتوا و کیفیت | عکس‌های دقیق، اسناد سازنده، بازبینی مشخصات و ممیزی نهایی سایت تکمیل شود |

جزئیات راه‌اندازی، نگهداری داده و بکاپ در [راهنمای استقرار](DEPLOYMENT.md) آمده است. بکاپ هاست اشتراکی و JetBackup به‌طور خودکار به معنی وجود همان خدمات در پلن VPS نیست.
