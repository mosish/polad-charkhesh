# Public light and dark appearance

The public site defaults to Automatic: light from 07:00 inclusive until 19:00 exclusive, dark otherwise, using the visitor device's local time and timezone. These are fixed clock hours, not calculated sunrise/sunset. No location permission or network time service is needed.

The bilingual public header has a three-position pill toggle: moon on the left, Auto in the center, sun on the right in both languages. A softly springing orb marks the selected preference: a cratered moon at the left and a golden sun at the right. Local SVG cloud layers and stars form a clipped sky scene; in Automatic the centered glass orb retains the Auto label while the sky follows the resolved day/night appearance. No video, external assets or animation library are loaded. No time explanation appears in the control. Native radio inputs support keyboard arrows, focus and screen readers, and reduced motion disables all control transitions. Manual choices remain saved and take priority until Automatic is selected again. Existing light/dark preferences are respected.

The `pc-theme` preference is stored separately for each origin. Missing, invalid or inaccessible stored preferences select Automatic. An external synchronous bootstrap resolves the appearance before stylesheet paint under the existing CSP. It owns the clock and storage policy; React observes that controller rather than duplicating the rules. On an open page, it checks at each minute boundary and refreshes after focus, visibility changes and restored navigation. Storage changes synchronize tabs on the same origin. If storage is blocked, a manual choice remains usable for the current visit. Administration uses the same saved appearance preference and automatic local-time policy. A persistent appearance/language bar is available on login, MFA and authenticated screens. Workspace surfaces have dedicated light-theme overrides; switching appearance does not remount editors or change authentication.

The cold silver/navy light palette applies to public home, catalog, product, engineering, dialog and recovery views. Existing dark styling, catalog records and engineering behavior are retained. The page palette changes directly; only the compact toggle scene animates.

Validation covers day/night boundaries, existing manual preferences, automatic resets, storage changes, timer/focus updates, blocked storage and administration appearance, plus the existing regression suite, typecheck, lint, production build/budgets and smoke. Browser checks simulate different visitor timezones and clock transitions, as well as persisted manual overrides and the bilingual mobile toggle, keyboard selection, reduced motion and responsive header layout. Production publication is separate from this review branch.

The compact sky toggle is 144 × 46 px (previously 158 × 52), with a 36 px orb and 44 px-high radio hit areas. The adjacent 100 × 46 px FA/EN language toggle uses the same inset capsule, glass thumb, spring motion and reduced-motion behavior, with a subtle globe motif. It reuses the existing language-switch handler: explicit selection of the inactive language switches once and closes mobile navigation; selecting the current language does nothing. Domain defaults, cross-domain switching, URL path/query/hash preservation and RTL/LTR behavior remain governed by the platform context.

Hero assembly, playback and speed controls share the inset glass track and springing indicator. Playback has explicit Pause/Play choices; all existing 0.5× / 1× / 1.5× rates are directly available. The native radio controls preserve keyboard selection, 44 px hit areas and reduced motion. Assembly selection still enters manual view, including reaffirming the selected endpoint, and scrolling restores Follow Scroll. While following, the indicator reflects the nearer assembly endpoint rather than a stale manual choice. The continuous bearing background, renderer settings and illustration disclaimer are retained.

The Company/About link targets the lower company section (`#about`), before support and contact; the earlier introductory section uses `#introduction`. Contact is always adjacent to Company in public navigation, including existing CMS menus, without rewriting stored menus or duplicating an existing contact entry. Header section links retain the active preview language and same-page query. The measured sticky header height governs anchor padding, including menu closure on mobile. Initial HTML uses the same destinations.

Lower home anchors receive a bounded four-second layout correction while lazy workspaces above them load. Wheel, touch, pointer and keyboard interaction cancel it immediately; ordinary browsing is never held at the destination. This was verified with a delayed catalog chunk and a subsequent manual scroll.

Admin UI checks use locally intercepted authentication/dashboard fixtures; no account or production data was created or changed. Form draft retention after appearance/language switches and 100 workspace/language/theme/viewport combinations were checked. Integration tests and production smoke cover the actual authentication and save flows separately.
